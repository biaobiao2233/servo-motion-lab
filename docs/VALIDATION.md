# 验证与证据规则

## 状态

- NOT_RUN：尚未执行。
- BLOCKED：明确缺少环境、组件、许可或授权。
- UNKNOWN：执行过，但证据缺失或无法证明结果。
- FAIL：有完整证据表明验收不满足。
- PASS：以下对应项目具备真实、完整且绑定候选的证据。

静态代码检查、工具测试、包安装成功、服务正在运行都不是轴运动 PASS。

## 最低验收

| 检查 | 必须记录 |
|---|---|
| 环境 | XAE/XAR/NC/PTP/库版本、专用 Runtime 身份、许可是否有效 |
| 构建 | 源提交/工作树身份、TwinCAT 原生构建开始/结束、完整日志与诊断 |
| 轴绑定 | AXIS_REF 与实际 NC 轴、仿真设置、单位/限位、目标实例 |
| 顺序定位 | 30、80、0 mm 三次实际反馈，Busy/Done/Error 与位置误差 |
| 运动中停止 | 命令发出时轴在运动、MC_Stop 反馈、实际速度与最终位置 |
| 越界拒绝 | 请求 -1 或 101 mm 被拒绝，NC 未执行越界运动 |
| 错误/复位 | 实际或明确注入的错误来源、ErrorID、复位反馈；未测则单独标记 |
| 清理/复演 | 自有进程退出、原实例保持、完整复演步骤 |

位置容差、停止速度阈值及采样间隔必须在测试前明确；超时只能判失败/不完整。
曲线必须来自实际 Runtime 的采样数据，不能由示意数据生成后称为测试结果。

公开 `evidence/` 只保存脱敏数据；本机原始日志和许可文件保存在被忽略目录。
验收报告写明 source commit、软件环境、观测时间、测试步骤、实际值和日志/CSV 哈希。
